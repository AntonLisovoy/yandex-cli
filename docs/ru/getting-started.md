# Начало работы

`yandex` — это программа, в которой вы набираете команды. Она обращается к
Yandex Tracker и Yandex Wiki, поэтому посмотреть список своих задач,
прочитать любую из них, оставить комментарий или выгрузить отчёт можно, не
открывая браузер.

Эта страница проведёт вас от «ничего не установлено» до первой работающей
команды. Она рассчитана на человека, который никогда раньше не открывал
терминал. В каждом шаге написано, что именно набрать и что должно появиться в
ответ.

## Что понадобится

- **Компьютер с macOS на Apple Silicon (M1 и новее) или с Linux на x86_64.**
  Опубликованы только эти две сборки. Для Mac на процессоре Intel и для машины
  с Linux на процессоре ARM готовой сборки нет и поддерживаемого способа
  установки тоже нет; если она вам нужна, заведите задачу на
  <https://github.com/AntonLisovoy/yandex-cli/issues>.
- **На Windows — WSL.** Напрямую в Windows `yandex` не работает. Установите
  подсистему Windows для Linux (WSL) — это настоящий Linux внутри Windows — и
  дальше выполняйте инструкцию для Linux уже внутри неё. Руководство Microsoft:
  <https://learn.microsoft.com/windows/wsl/install>.
- **Учётная запись в Yandex Tracker**, в которую вы уже умеете входить через
  браузер.
- **OAuth-токен и идентификатор организации.** Это две короткие строки: одна
  доказывает Tracker, что вы — это вы, другая говорит, о какой организации вы
  спрашиваете. Сейчас их у вас нет; шаги 4 и 5 объясняют, как их получить.

## 1. Откройте терминал

Терминал — это окно, в котором вы набираете команды вместо того, чтобы щёлкать
мышью.

- **macOS:** нажмите `Cmd`+`Space`, наберите `Terminal`, нажмите `Enter`.
- **Linux:** в большинстве графических окружений — `Ctrl`+`Alt`+`T`. Если
  ничего не произошло, откройте меню приложений и найдите `Terminal`.

Откроется окно, в котором строка текста заканчивается чем-то вроде `$` или `%`.
Это *приглашение*: оно означает, что терминал ждёт. Вы набираете команду после
него и нажимаете `Enter`, чтобы её выполнить. Когда команда закончит работу,
приглашение появится снова.

## 2. Установка

Установить можно двумя способами, и нужен только один. Если у вас Mac и вы уже
пользуетесь Homebrew — ставьте через Homebrew. Иначе используйте
установщик-скрипт.

### Homebrew (macOS)

Homebrew — это менеджер пакетов, то есть программа, чья работа состоит в
установке других программ; ею пользуется большинство разработчиков на Mac. Если
его у вас нет, команда установки в одну строку есть на <https://brew.sh>.

```bash
brew install AntonLisovoy/tap/yandex-cli
```

### Установщик-скрипт (macOS и Linux)

Скопируйте эту строку целиком, вставьте её после приглашения и нажмите `Enter`:

```bash
curl -LsSf https://raw.githubusercontent.com/AntonLisovoy/yandex-cli/main/install.sh | sh
```

Установщик скачивает сборку для вашей машины, сверяет её с опубликованной
контрольной суммой SHA256 и отказывается продолжать, если они не совпали,
распаковывает её в `~/.local/share/yandex-cli/<version>` и делает ссылку
`~/.local/bin/yandex` на неё. `~` — это ваша домашняя папка, так что оба пути
лежат внутри неё: ничего общесистемного не устанавливается и пароль не
спрашивается.

Он печатает две строки с версией, которую скачал. У вас будет та версия,
которая вышла к этому моменту, — например:

```
Downloading yandex-cli-1.0.0-macos-arm64...
Installed yandex 1.0.0 to /Users/you/.local/bin/yandex
```

Ваша командная оболочка — программа, которая читает то, что вы набираете в
терминале, — ищет команды только в папках из списка, который она хранит; этот
список называется PATH. Если `~/.local/bin` в этом списке нет, установщик
скажет об этом и подскажет строку, которую нужно добавить:

```
Note: /Users/you/.local/bin is not on your PATH. Add it:
  export PATH="/Users/you/.local/bin:$PATH"
```

Если выполнить эту строку, `yandex` заработает в открытом сейчас окне, но не в
следующем. Как закрепить это навсегда, написано на
[странице решения проблем](troubleshooting.md#команда-не-найдена).

## 3. Проверьте, что всё получилось

Наберите это и нажмите `Enter`:

```bash
yandex --version
```

Вы должны увидеть версию, которую только что установили, в таком виде — сами
цифры зависят от того, когда вы её ставили:

```
yandex, version 1.0.0
```

> **Вместо этого появилось `command not found: yandex`?** Программа
> установлена, но оболочка не знает, где её искать, — это и есть та самая
> заметка про PATH из предыдущего шага. Как исправить, написано на
> [странице решения проблем](troubleshooting.md#команда-не-найдена).

## 4. Получите OAuth-токен

OAuth-токен — это длинная строка, которая позволяет `yandex` действовать в
Tracker от вашего имени. Вы создаёте его один раз в браузере, и правильной
инструкцией здесь остаётся страница самого Яндекса: она не устаревает, когда
интерфейс меняется.

<https://yandex.ru/support/tracker/ru/concepts/access>

Пройдите её в соседней вкладке и вернитесь с тем, что она выдаст: длинной
строкой, начинающейся с `y0_`. Это всё, что нужно от неё этому руководству.

**Обращайтесь с ним ровно как с паролем.** Любой, у кого он есть, может читать
и менять в Tracker всё то же, что и вы. Не вставляйте его в чат, в задачу, в
скриншот или в git-коммит. Если вам кажется, что он утёк, отзовите приложение
на <https://oauth.yandex.ru> и выпустите новый токен.

## 5. Найдите идентификатор организации

Tracker нужно знать, о какой организации вы спрашиваете. Идентификаторы бывают
двух видов, и **вам подходит ровно один из них**:

| Ваша организация | Какую настройку использовать |
|---|---|
| Управляется в Yandex Cloud | `TRACKER_CLOUD_ORG_ID` (`--cloud-org-id`) |
| Yandex 360 или локальная установка | `TRACKER_ORG_ID` (`--org-id`) |

Где смотреть:

- **В Tracker.** Откройте <https://tracker.yandex.ru/admin/orgs> или нажмите
  *Администрирование → Организации* в самом Tracker. На странице перечислены
  ваши организации; скопируйте значение поля с идентификатором.
- **В Yandex Cloud.** Откройте <https://center.yandex.cloud> и войдите.
  Идентификатор организации показан под её названием на главной странице;
  щёлкните справа от него, чтобы скопировать.

Если вы не уверены, какой из двух видов у вас, попробуйте один прямо в
командной строке, ничего не сохраняя. Токен и идентификатор, переданные
опциями, не оставляют следов на диске, так что второй вариант можно попробовать
сразу же:

```bash
yandex --token y0_... --org-id 123456 config check
```

```bash
yandex --token y0_... --cloud-org-id bpf1abc2def3ghi4jkl5 config check
```

Один из двух ответит `✓ Connected as <your name>`. Именно этот вариант и надо
сохранить на шаге 6. Если же Tracker отказывается принимать данные, последняя
строка ошибки называет заголовок, который был отправлен на самом деле, —
`X-Org-ID=...` или `X-Cloud-Org-ID=...`, — так что видно, какой из двух вы
только что попробовали.

**Никогда не задавайте оба сразу.** CLI останавливается, ничего не отправив:

```
  ✗ Both org_id and cloud_org_id are set — the API accepts exactly one.
      Unset TRACKER_ORG_ID or TRACKER_CLOUD_ORG_ID (or pass only one of --org-id / --cloud-org-id).
```

Именно поэтому в пробе выше используются опции, а не сохранённый профиль:
сохранение профиля дважды *объединяет* обе попытки, оставляя в нём оба
идентификатора и выдавая ровно эту ошибку каждый раз. Если это уже случилось,
удалите профиль командой `yandex config delete-profile work` и сохраните его
заново, указав только нужный идентификатор.

## 6. Сохраните профиль

Профиль — это токен и идентификатор организации, записанные один раз в файл,
который `yandex` читает при каждом запуске. Подставьте свои токен и
идентификатор и возьмите ту из двух опций, которая сработала на шаге 5:

```bash
yandex config set-profile work --token y0_... --org-id 123456
```

```bash
yandex config set-profile work --token y0_... --cloud-org-id bpf1abc2def3ghi4jkl5
```

Любая из них печатает:

```
  profile: work
  config_file: /Users/you/.yandex-cli/config.json
  current: True
  saved: True
  ✓ Profile 'work' saved to /Users/you/.yandex-cli/config.json
```

Теперь проверьте, что Tracker его принимает:

```bash
yandex config check
```

Он отвечает вашим именем и версией, на которой вы работаете, — например:

```
  ✓ Connected as John Doe (j.doe)
  backend: yandex-cli 1.0.0
  api_base_url: https://api.tracker.yandex.net
  wiki_base_url: https://api.wiki.yandex.net
  org_id: 123456
  cloud_org_id: -
```

Если имя ваше — с настройкой покончено. Последние две строки показывают, какой
именно идентификатор вы сохранили: у организации в Yandex Cloud заполнено
`cloud_org_id`, а в `org_id` стоит `-`.

**Почему профиль, а не `export TRACKER_TOKEN=...`?** Экспортированная
переменная живёт только в том окне терминала, где вы её набрали; закройте окно —
и её нет. Файл `.env` читается только тогда, когда вы запускаете `yandex` из
каталога, где он лежит, поэтому одна и та же команда в одной папке работает, а
в другой — нет. Профиль работает везде и всегда. Оба других способа тоже
рабочие, и они описаны в [настройке](configuration.md).

Посмотреть, что CLI считает своими текущими настройками:

```bash
yandex config show
```

Токен выводится замаскированным: только первые и последние четыре символа и
длина. Строки `config_file` и `session_file` не маскируются и содержат ваше имя
пользователя, так что перед отправкой вывода в отчёт об ошибке их стоит
обрезать.

## 7. Первые команды

**Посмотрите список доступных очередей.** Очередь группирует задачи команды и
задаёт им префикс ключа — `TREK`, `OPS` и так далее.

```bash
yandex tracker queue list
```

```
  Queues
  ──────
  KEY  │ NAME        │ ID │ DEFAULT TYPE │ DEFAULT PRIORITY
  ─────────────────────────────────────────────────────────
  TREK │ Tracker CLI │ 1  │ Задача       │ Normal
  OPS  │ Operations  │ 2  │ Задача       │ Normal
  2 row(s)
```

**Найдите свои открытые задачи.** Текст после `-q` — это поисковый запрос
Tracker на том же языке, который понимает строка поиска в веб-интерфейсе.

```bash
yandex tracker issue find -q "Assignee: me() AND Resolution: empty()"
```

```
  Issues matching 'Assignee: me() AND Resolution: empty()'
  ────────────────────────────────────────────────────────
  KEY    │ SUMMARY                     │ STATUS │ TYPE   │ PRIORITY │ ASSIGNEE │ UPDATED
  ──────────────────────────────────────────────────────────────────────────────────────
  OPS-1  │ Rotate the tokens           │ Открыт │ Задача │ Normal   │ John Doe │ -
  TREK-1 │ Design the CLI command tree │ Открыт │ Задача │ Normal   │ John Doe │ -
  TREK-2 │ Implement the session store │ Открыт │ Задача │ Normal   │ John Doe │ -
  TREK-3 │ Write the export pipeline   │ Открыт │ Задача │ Normal   │ John Doe │ -
  4 row(s)
```

**Прочитайте одну из них.** Возьмите ключ из своего собственного списка.

```bash
yandex tracker issue get TREK-1
```

```
  Issue TREK-1
  ────────────
  key: TREK-1
  summary: Design the CLI command tree
  status: Открыт
  type: Задача
  priority: Normal
  assignee: John Doe
  created: -
  updated: -
  version: 1
  tags: ["cli"]
  url: https://tracker.yandex.ru/TREK-1

  Description
  ───────────
Description of TREK-1
```

Набирать `TREK-1` в каждой команде быстро надоедает, поэтому CLI запоминает
задачу, над которой вы работаете. Скажите ему об этом один раз:

```bash
yandex session use-issue TREK-1
```

и с этого момента `yandex tracker issue get` без ключа означает именно эту
задачу — пока вы не укажете другую. Подробно об этом — в
[командах](commands.md#сессия-что-запоминает-cli).

## 8. Интерактивный режим

Вместо того чтобы набирать `yandex` в начале каждой строки, программу можно
запустить один раз и остаться внутри:

```bash
yandex repl
```

Запуск `yandex` вообще без аргументов делает то же самое.

Внутри приглашение выглядит как `◆ yandex ❯`, а когда появляется текущая
задача, к нему добавляется метка `[TREK-1]`. Команды набираются **без**
префикса `yandex`: `tracker queue list`, а не `yandex tracker queue list`.

По команде `help` выводится список групп:

```
  Commands
  ────────
  tracker queue ...     queues: list, get, tags, versions, fields
  tracker field ...     metadata: global, statuses, types, priorities, resolutions
  tracker issue ...     issues: find, get, create, update, transition, close, worklog-*
  tracker board ...     boards and sprints: list, get, create, update
  tracker template ...  issue and comment templates: issue-list, comment-list
  tracker user ...      users: list, search, get, me
  tracker project ...   projects, portfolios, goals, entities
  wiki ...              wiki: page *, grid *, attachment *, comment *, access *, search
  export ...            write issues to json/csv/md
  session ...           status, use-queue, use-issue, history, undo, clear
  config ...            show, check, profiles
  help                  this listing
  quit / exit           leave the REPL
```

`quit`, `exit` или `Ctrl`+`D` возвращают вас к обычному приглашению. Стрелка
вверх подставляет то, что вы набирали раньше, в том числе в прошлых запусках:
история хранится в `~/.yandex-cli/history`.
